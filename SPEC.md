# SPEC — D2Helper (сайт‑помощник для Dota 2)

> Актуальное ТЗ: что сделано и какие решения приняты. Подробности — в коде. Проект пишется с нуля: свой код, вёрстка и тексты; чужие логотипы, баннеры и тексты не используем. Название — константа `APP_NAME` (бэк: env, фронт: `VITE_APP_NAME`), в разметке не хардкодить.

## 0. Статус

Все этапы 1–9 выполнены, дипломный проект готов. Дальше — исправление багов, найденных при тестировании, и доработка деталей.

Что есть: мета по позициям, новости и патчноуты, «Тренер» (профиль, синк матчей, сводка, страница матча), «Больше/Меньше», квизы, поиск пати и анкета, профиль, драфтер (анализ, тренировка, история, топ), герои, **глубокий AI‑разбор матча по реплею** и вкладка «Разборы».

## 1. Стек и решения

Go 1.23+ (chi, pgx/v5, goose, slog), PostgreSQL 16, React 18 + TS + Vite, React Router **v7** (импорты из `react-router`), TanStack Query v5, Zustand, Tailwind 4 (токены через `@theme inline` в `styles/index.css`), lucide‑react, framer‑motion. Кэш — в процессе, константы дополнительно в `kv_cache`. UI на русском, все строки в `frontend/src/i18n/ru.ts`. Деплой: `docker-compose.yml` (postgres, backend, nginx+статика, `/api` проксируется, сайт на порту 8000).

Данные: OpenDota (профиль, матчи, константы, парсинг реплеев), STRATZ GraphQL (мета по позициям, матчапы, средние K/D; без токена — фоллбэк на OpenDota; **схему сверять интроспекцией**), Steam (новости, ники), dota2.com datafeed (патчноуты).

Платежей нет — проект бесплатный (ЮKassa, тарифы, кредиты вырезаны). Таблицы `products`, `orders`, `credit_ledger` и колонки `users.analysis_credits`, `has_paid` остались в миграциях неиспользуемыми.

### Сознательные решения (не «чинить»)
- `--text-dim` = #7C7D84 и тёмный текст на кнопках `--accent-2` (`--on-accent`) — иначе не проходит контраст 4.5:1.
- Нижняя навигация из 6 вкладок (Главная, Играть, Тренер, **Разборы**, Инструменты, Профиль); при ширине <440px «Утилиты» вместо «Инструменты», при <400px шрифт подписей 10px.
- Вход: ник/аватар сначала из Steam, потом из OpenDota; логин защищён nonce‑cookie `oid_nonce`; `POST /auth/logout` отвечает 204 даже без сессии. `PUBLIC_URL` в dev может быть пустым (адрес по Host). `PATCH_LABEL` используется, только пока совпадает с текущим патчем.
- **Мета.** Без STRATZ герой попадает только на основную позицию (первая в `positions` из `heroes_tags.json`). С STRATZ — только если у него ≥1% игр позиции и позиция ≥30% его игр (иначе в топе редкие роли вроде Tidehunter‑керри). Минимум 200 матчей на позицию.
- **Новости.** Новость про патч (в заголовке «patch» + номер) показывает окно патча с dota2.com (на русском) и комментарии; комментировать могут только вошедшие. Перевод новостей на русский не делается.
- **Поиск пати.** Анкеты и поиск доступны только вошедшим. В анкете есть `goal` (rating/fun/stack/scrim) и `looking_for` (team/players); вкладки `?tab=team|players`: «Найти команду» показывает анкеты с `looking_for=players`, «Найти игрока» — с `team`. Правка анкеты не меняет время подъёма и видимость; «поднять» — раз в 24ч; `party_expire` скрывает анкеты без активности >14 дней; ≥3 жалоб скрывают анкету до проверки. Ошибки валидации — `validation_failed` с `fields`.
- **HeroPicker** ищет только по английским названиям (русских имён героев в данных нет).
- **Драфтер.** Матрица `GET /drafter/matrix` кэшируется на 1 час с ETag (состав «играбельных» героев меняется мета‑джобой раз в 3ч и едёт в том же ответе). Оценка героя `score(h) = Σ vs(h,e) + 0.5 × Σ with(h,a)` для союзников, округление до 0.1 «от нуля» совпадает на клиенте (`lib/drafter.ts`) и сервере (`internal/drafter`). Оценка тренировки считается только на сервере: `raw = Σ_h[Σ vs + 0.5 Σ with + META_WEIGHT·(wr_pos − 0.5)] − OFFPOS_PENALTY·(героев не на позиции)`, `score = clamp(50 + raw·SCALE, 0, 100)`. Подобрано по данным STRATZ: `DRAFTER_SCORE_SCALE=1.1`, `DRAFTER_META_WEIGHT=10`, `DRAFTER_OFFPOS_PENALTY=3`, `DRAFTER_TRAININGS_PER_HOUR=60` (случайный драфт ≈ 50, почти идеальный ≈ 90). Враги в тренировке — по герою на позицию из «играбельных», с весами по популярности. Лидерборд — календарный месяц (Europe/Moscow), сумма 5 лучших счётов (меньше 5 — все), топ‑100, кэш 5 мин. Неоценённые тренировки удаляет `drafter_cleanup` (>7 дней); открытая тренировка и собранная пятёрка лежат в localStorage.
- **Матчапы.** `hero_matchups`: `vs` — преимущество героя `a` над `b` в п.п. (STRATZ; OpenDota: `wins/games − базовый winrate`, ×100, если `games ≥ 50`); `with` — синергия (только STRATZ, без него 0 и блок «Сильнейшая пара» скрыт).

## 2. Дизайн и вёрстка

Тёмная тема, контент одной колонкой по центру; токены — в `frontend/src/styles/index.css`. Скругления: карточки 16, кнопки 14, плашки 10. Шрифты Inter и JetBrains Mono. Готовый UI‑кит в `components/ui` (витрина `/dev/ui`) — переиспользовать. Ширину колонки задаёт `<Page width={N}>`:

| Страница | Ширина |
|---|---|
| Хаб инструментов, Герои, Профиль, Разборы, запуск разбора | 760 |
| Драфтер | 1160 (основная колонка 760 + sticky‑панель 376) |
| История/Топ драфтеров, Страница героя, Анкета пати, Результат разбора | 1000 |
| Поиск пати | 1200 |

Главное разрешение — 1920×1080 (под контент ≈790px); проверять также 1536×864, 1366×768, 768 и 360px. Ниже 1280px двухколоночные раскладки становятся одной колонкой, ниже 768px — мобильная вёрстка. У каждого экрана с данными: скелетон, empty state, error state с «Повторить». Hover, видимый focus, Tab‑навигация, `aria-label` у иконок‑кнопок, контраст ≥4.5:1. Картинки героев всегда с width/height.

## 3. Страницы (кратко)

- **Главная** `/`: мета патча по 5 позициям, последние новости. `/news`, `/news/:gid`, `/feedback`.
- **Играть** `/play`: «Больше/Меньше» (режимы Популярность/Убийства/Смерти, рекорды), квизы «Какая твоя позиция?» и «Подбор героя», поиск пати. «Битва драфтов» — заглушка «Скоро».
- **Тренер** `/coach`: гость — лендинг и поиск профиля по ссылке/SteamID; вошедший — «Мои матчи» (последние 20, фильтры, подгрузка), сводка `/coach/summary`, страница матча `/coach/matches/:id`; закрытая история → инструкция и «Проверить снова».
- **Разборы** `/reviews`: вкладка «Все разборы» (список со статусами, оценкой, героем; неудавшийся ведёт на повторный заказ) и «Что тренировать» (`?tab=train`: чек‑лист плана из последнего разбора и «Что улучшить» из трёх последних). Гость — вход через Steam и ссылка на пример. Запуск `/coach/deep` и результат `/coach/analysis/:id` тоже относятся к этой вкладке; «назад» ведёт в `/reviews`.
- **Инструменты** `/tools`: Драфтер `/tools/drafter` (`?tab=analysis|training`, состояние анализа в URL `?r=1:12,2:45&d=…&b=…`), история и топ драфтеров, Герои `/tools/heroes` (сильные по позициям, поиск, сетка с фильтрами), страница героя `/tools/heroes/:id` (позиции, матчапы, союзники, предметы, «Взять в драфтер»).
- **Профиль** `/profile`: аккаунт, карточка анкеты, «Игры» (рекорды, последние квизы, место драфтера), анкета `/profile/party-card`.

## 4. Глубокий разбор (AI)

Бесплатный, дневной лимит `ANALYSES_PER_DAY` (по умолчанию 3; неудавшиеся разборы лимит не тратят). Флаг `FEATURE_DEEP_ANALYSIS`; `features.deep_analysis` в `/api/config` = разбор включен **и** модель подключена; без неё страницы показывают «Разбор пока недоступен» и пример.

**Модель.** `internal/llm` — один клиент для любых OpenAI‑совместимых API (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`): OpenRouter (по умолчанию, бесплатные модели), Ollama, Groq, Gemini. `LLM_MODEL` — список через запятую, пробуются по порядку (429/5xx/пустой ответ → следующая, два прохода; 401/403 → ошибка ключа; при 400 повтор без `response_format`).

**Пайплайн** (`internal/analysis`):
1. `POST /analyses {match_id}`: матч должен быть в истории отслеживаемого профиля (иначе 403); лимит (429 + `Retry-After`); повторный заказ возвращает существующий разбор (200), новый — 201.
2. Воркер (`ANALYSIS_MAX_PARALLEL`, по умолчанию 2) берёт `queued` через `FOR UPDATE SKIP LOCKED`; после рестарта зависшие `parsing`/`analyzing` возвращаются в очередь.
3. `parsing`: если реплей не разобран — запрос в OpenDota и опрос раз в 20 с до 15 минут; матч старше 14 дней недоступен.
4. `analyzing`: из реплея собираются компактные признаки игрока (линия, смерти, драки, ключевые покупки, золото по минутам, процентили, варды/стаки, выкупы); модель отвечает **строго JSON** по‑русски; ответ проверяется (`ParseAnswer`), один повтор при ошибке. Цифры (линия, ключевая статистика, точки смертей) берутся **из данных реплея**, а не из ответа модели.
5. `done` + `result`, либо `failed` с понятным текстом (частичный уникальный индекс `status <> 'failed'` позволяет заказать матч снова).

**Результат** (`AnalysisResult`): `summary{verdict, rating 1–10, key_stats[]}`, `lanes`, `episodes[]` (время, суть, ошибка, как лучше, серьёзность), `improvements[]` (3), `next_games_plan[]` (3–5), `death_points[]` (мини‑карта). Пример — `backend/data/analysis_example.json`, доступен всем (`/coach/analysis/example`). Отметки плана хранятся в localStorage по id разбора.

**Эндпоинты:** `POST /analyses`, `GET /analyses` (список до 50 для вкладки «Разборы»: статус, матч, оценка, улучшения, план), `GET /analyses/{id}`, `GET /analyses/quota`, `GET /analyses/example`.

## 5. API и фоновые джобы

Префикс `/api`, формат ошибок `{ "error": { "code", "message", "fields"? } }`; полный перечень — `backend/internal/httpapi/router.go`. Rate limit по IP на POST (30/мин) и отдельно на дорогие ручки; CSRF: SameSite=Lax + проверка Origin на мутациях.

Джобы (горутины в `cmd/server`): `constants_refresh`, `meta_positions` (3ч), `news_refresh` (30м), `higher_lower_snapshot` (24ч), `sessions_cleanup`, `stratz_check`, `party_expire` (1ч), `matchups` (24ч), `drafter_cleanup` (6ч), `analysis_worker` (непрерывно).

## 6. Данные в репозитории

`backend/data/`: `heroes_tags.json` (127 героев: позиции — первая основная, сложность 1–3, тайминг, теги), `quiz_position.json`, `quiz_hero.json`, `positions.json`, `analysis_example.json`. При старте бэкенд логирует героев без тегов. Миграции goose — `backend/migrations` (встроены в бинарник).

## 7. Качество

Go: `go vet`, unit‑тесты на ключевую логику, клиенты внешних API за интерфейсами (`golangci-lint` локально не установлен). Фронт: eslint + prettier + vitest для `lib/` и логики, `strict` TS, страницы через `React.lazy`. Безопасность: лимиты длины текстовых полей, санитизация HTML, никаких секретов во фронте.
